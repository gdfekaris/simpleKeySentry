# Bitcoin extended private key false positives — must NOT match.
#
# These strings have the *exact* shape of a real xprv/yprv/zprv/tprv
# (correct prefix, correct length, all base58 characters) but the trailing
# 4-byte checksum is wrong. The regex first-pass accepts them; the
# base58check validator rejects them. This is the entire reason the
# validator exists — without it, the regex alone would emit Findings on
# any 111-character base58 string starting with `xprv`.
#
# Each entry is constructed by taking a true positive and swapping a
# single character; the SHA-256d checksum collision rate is ~1/2^32, so
# mutation reliably breaks the checksum.
